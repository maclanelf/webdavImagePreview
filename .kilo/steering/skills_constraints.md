# Skills 使用强制约束

当使用 `identify_creator` 或 `insert_creators` skill 时，必须严格遵守以下规则：

## 🚨 绝对禁止的行为

1. **禁止创建任何文件**
   - 不得创建任何 .py、.js、.sh、.bat 等脚本文件
   - 不得创建配置文件、日志文件、临时文件
   - 不得创建任何辅助工具或自动化脚本

2. **禁止修改现有脚本**
   - 不得修改 `identify_creator.py`
   - 不得修改 `insert_creators.py`
   - 不得"优化"、"改进"、"修复"脚本代码

3. **禁止编写自动化代码**
   - 不得使用正则表达式提取博主名
   - 不得使用字符串分割/路径解析
   - 不得编写任何形式的自动提取逻辑
   - 即使看到"明显的规律"也不得用代码处理

4. **禁止自作主张**
   - 看到剩余数量大（如 10000+）→ 不是写脚本的理由，继续用 skill
   - 遇到编码问题/乱码 → 报告问题，不要自行修改脚本或创建新脚本
   - 遇到性能问题 → 报告问题，不要自行优化
   - 遇到任何问题 → 报告即可，不要尝试"解决"

## ✅ 必须做的事情

1. **严格按脚本步骤执行**
   - 只运行脚本提供的命令
   - 按照 README.md 中的流程执行
   - 不要跳过步骤，不要合并步骤

2. **AI 人工分析路径 — 严格识别规则**

   **`moxing` 与 `xin` 的强制排除规则：**
   - 路径或文件描述中包含 `moxing` 时，禁止将该条数据识别、创建或关联为博主 `xin`。
   - 即使同一路径中也出现 `xin`，`moxing` 仍优先作为排除条件，不得归属给 `xin`。
   - 无法确认其他正确博主时，按当前 skill 流程跳过或标记为无法识别，不要猜测为 `xin`。
   
   **博主名必须符合以下特征：**
   - 像一个真实的网红/博主名字（如"不吃肉肉"、"小鱼儿"、"德克萨斯"）
   - 通常是人名、昵称、拟人化名称、角色名
   - 不是描述性文字、日期、数字编号、文件类型
   
   **从路径中提取博主名的优先级：**
   1. 优先从文件夹名提取（如 `/博主A/2024/视频.mp4` → "博主A"）
   2. 其次从文件名前缀提取（如 `/分类/博主B_标题.mp4` → "博主B"）
   3. 最后从特殊标记提取（如 `/[博主C] 作品集/` → "博主C"）
   
   **绝对不要从以下内容提取博主名：**
   - ❌ 文件扩展名（.jpg、.mp4、.mov 等）
   - ❌ 日期时间（2023-07-16、20240101 等）
   - ❌ 纯数字编号（001、125、7396874995999214898 等）
   - ❌ 描述性文字（"今天也是你的可爱茶"、"期待加班备了好久的旅拍大部队精" 等）
   - ❌ 技术标记（NO.001、[27P-20V]、dy无水印 等）
   - ❌ 标签符号（#肉丝、#御姐、#黑长直 等）
   - ❌ 通用分类（wb、IMG、SP、VMB001 等）
   
   **示例分析：**
   
   ✅ 正确：
   ```
   /不吃肉肉/2024/视频.mp4 → "不吃肉肉"
   /小鱼儿_日常_20240101.mp4 → "小鱼儿"
   /[德克萨斯] 作品集/001.jpg → "德克萨斯"
   /辛普森的小兔子/微博精选/图.jpg → "辛普森的小兔子"
   /平台/分类/描述性文字/王艺璇/子目录/文件.jpg → "王艺璇"（人名在深层目录中）
   ```
   
   ❌ 错误：
   ```
   /path/今天也是你的可爱茶 2020-02-11 3.jpg → "今天也是你的可爱茶"（这是描述性文字，不是博主名）
   /path/7396874995999214898#真相只有一个.mp4 → "7396874995999214898"（这是数字编号，不是博主名）
   /path/dy无水印作品.mp4 → "dy无水印"（这是技术标记，不是博主名）
   /平台/描述/编号/描述/文件.jpg → 跳过（没有明显的人名或昵称）
   ```
   
   **关键识别技巧：**
   - 人名通常是 2-4 个汉字（如"王艺璇"、"不吃肉肉"）
   - 昵称通常有拟人化特征（如"小鱼儿"、"辛普森的小兔子"）
   - 描述性文字通常是完整的句子或短语（如"今天也是你的可爱茶"）
   - 即使路径很长、层级很深，也要仔细查找人名/昵称
   - 不要被前面的描述性文字干扰，继续往下找
   
   **无法判断时：**
   - 如果路径中没有明显的博主名特征，直接跳过
   - 不要从文件名的描述性内容中强行提取
   - 宁可跳过，也不要错误识别

3. **遇到问题时报告**
   - 脚本报错 → 复制完整错误信息，询问用户
   - 数据异常 → 描述异常情况，询问用户
   - 不确定如何处理 → 询问用户，不要自行决定

## 为什么有这些约束

**路径格式完全不固定，没有任何规律可循：**

```
/博主A/2024/视频.mp4                          ← 文件夹即博主名
/分类/博主B_标题_日期.mp4                      ← 下划线分隔
/[博主C] 作品集/IMG_001.jpg                   ← 方括号包裹
/cos/明日方舟/德克萨斯/德克萨斯_001.jpg        ← 游戏角色名
/街拍/2024-01-15_商场_疑似网红.mp4            ← 描述性文件名
/下载/未分类/20240101_123456.mp4              ← 完全无法识别
```

只有 AI 能理解语义并正确判断，任何代码自动提取都会出错。

## 关于编码乱码问题

**如果你看到路径显示为乱码（如 `鈥?`、`锝炪€?` 等）：**

1. **这是 Windows PowerShell 编码问题，不是脚本错误**
2. **路径数据本身是正确的，只是显示乱码**
3. **你仍然可以正确分析路径**（因为你接收到的是原始 UTF-8 数据）
4. **不要尝试修改脚本或创建新脚本来"修复"乱码**
5. **如果实在无法阅读，报告给用户，让用户调整 PowerShell 编码**

**正确做法：** 即使显示乱码，仍按原样分析路径中的博主名，因为你能看到正确的数据。

**错误做法：** 创建新脚本、修改编码设置、尝试"修复"输出。

## 违反约束的后果

如果你违反了上述约束（创建文件、修改脚本、编写自动化代码），会导致：
- 数据错误（博主名识别错误）
- 流程混乱（用户无法追踪进度）
- 维护困难（临时脚本散落各处）

**请严格遵守约束，不要自作主张。**
