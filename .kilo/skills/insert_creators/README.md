## 🚨 AI 强制约束 — 必须无条件严格遵守

### 绝对禁止的行为：

1. **禁止用代码自动提取博主名**
   - 不得使用正则、字符串分割、路径解析等任何代码手段
   - 不得编写任何语言的自动提取脚本
   - 不得基于路径格式假设（如"第一个文件夹就是博主名"）

2. **必须 AI 人工逐条分析**
   - 每条路径必须由 AI 亲自阅读，语义理解后判断博主名
   - 路径格式完全不固定，没有任何规律可循，只有 AI 能正确理解

3. **为什么不能用代码提取：**

```
/博主A/2024/视频.mp4                          ← 文件夹即博主名
/分类/博主B_标题_日期.mp4                      ← 下划线分隔
/[博主C] 作品集/IMG_001.jpg                   ← 方括号包裹
/cos/明日方舟/德克萨斯/德克萨斯_001.jpg        ← 游戏角色名
/街拍/2024-01-15_商场_疑似网红.mp4            ← 描述性文件名
/下载/未分类/20240101_123456.mp4              ← 完全无法识别
```

只有 AI 能理解语义并正确判断，脚本无法处理这种不规则格式。

## 执行流程

### 步骤1：获取待分析路径

```bash
python .kilo/skills/insert_creators/insert_creators.py
# 或指定批量数
python .kilo/skills/insert_creators/insert_creators.py --batch 20
```

脚本自动执行：
- 从上次处理的 ID 开始顺序获取文件（不再随机）
- 提取目录路径去重（同一目录只取一个文件）
  - 例如：`/博主A/2024/1.jpg` 和 `/博主A/2024/2.jpg` 只取一个
  - 大幅减少需要分析的文件数量（同一目录通常是同一博主）
- 排除包含已有博主名的文件
- 记录最大 ID，下次从此处继续

**为什么使用顺序处理 + 目录去重：**
- 顺序处理：不会重复处理同一批文件，可随时中断和继续
- 目录去重：同一目录的文件通常是同一博主，只需分析一个即可
- 例如：1000 个文件可能只有 50 个不同目录，只需分析 50 条路径

**批量数量建议：**
- 推荐：10-20 条（平衡效率与准确性）
- 最多：100 条（技术上限）

### 步骤2：AI 人工分析路径

AI 逐条阅读路径，语义判断博主名。

**博主名必须符合以下特征：**
- 像一个真实的网红/博主名字（如"不吃肉肉"、"小鱼儿"、"德克萨斯"）
- 通常是人名、昵称、拟人化名称、角色名
- 不是描述性文字、日期、数字编号、文件类型

**从路径中提取博主名的优先级：**
1. 优先从文件夹名提取（如 `/博主A/2024/视频.mp4` → "博主A"）
2. 其次从文件名前缀提取（如 `/分类/博主B_标题.mp4` → "博主B"）
3. 最后从特殊标记提取（如 `/[博主C] 作品集/` → "博主C"）

**绝对不要从以下内容提取博主名：**
- ❌ 文件扩展名（.jpg、.mp4、.mov 等）
- ❌ 日期时间（2023-07-16、20240101 等）
- ❌ 纯数字编号（001、125、7396874995999214898 等）
- ❌ 描述性文字（"今天也是你的可爱茶"、"期待加班备了好久的旅拍" 等）
- ❌ 技术标记（NO.001、[27P-20V]、dy无水印 等）
- ❌ 标签符号（#肉丝、#御姐、#黑长直 等）
- ❌ 通用分类（wb、IMG、SP、VMB001 等）

**示例：**

✅ 正确识别：
```
/不吃肉肉/2024/视频.mp4 → "不吃肉肉"
/小鱼儿_日常_20240101.mp4 → "小鱼儿"
/[德克萨斯] 作品集/001.jpg → "德克萨斯"
/辛普森的小兔子/微博精选/图.jpg → "辛普森的小兔子"
/平台/分类/描述/王艺璇/子目录/文件.jpg → "王艺璇"（深层目录中的人名）
```

❌ 错误识别：
```
/path/今天也是你的可爱茶 2020-02-11 3.jpg → "今天也是你的可爱茶"（描述性文字）
/path/7396874995999214898#真相只有一个.mp4 → "7396874995999214898"（数字编号）
/path/dy无水印作品.mp4 → "dy无水印"（技术标记）
```

**关键识别技巧：**
- 人名通常是 2-4 个汉字（如"王艺璇"、"不吃肉肉"）
- 昵称通常有拟人化特征（如"小鱼儿"）
- 即使路径很长、层级很深，也要仔细查找人名/昵称
- 不要被前面的描述性文字干扰

**无法判断时：** 直接跳过，不要从文件名的描述性内容中强行提取。

**强制排除规则：** 如果路径或文件描述包含 `moxing`，禁止将该条记录识别或创建为博主 `xin`。即使同一路径还出现 `xin`，也不能归属给 `xin`；无法判断其他正确博主时直接跳过。

### 步骤3：去重处理（关键步骤）

**必须在执行任何插入命令之前完成去重。**

去重规则：
- 汇总所有识别出的博主名
- 如果多条路径识别出相同博主名，只保留第一条，舍弃后续重复
- 报告去重情况：`检测到重复博主名 'XXX'，已舍弃路径 N，保留路径 M`

去重后的博主名列表可以安全并发执行（每个名称唯一，不会冲突）。

### 步骤4：并发统一插入

对去重后的每个博主名，并发调用：

```bash
python .kilo/skills/insert_creators/insert_creators.py --create "博主A"
python .kilo/skills/insert_creators/insert_creators.py --create "博主B"
python .kilo/skills/insert_creators/insert_creators.py --create "博主C"
# ... 去重后所有博主名，可同时并发执行
```

脚本内部会再次确认博主不存在才插入（防止数据库已有同名）。

### 步骤5：继续下一批

```bash
python .kilo/skills/insert_creators/insert_creators.py
```

## ⚠️ Windows 编码问题

**问题：** 在 PowerShell 中运行脚本时，中文路径显示为乱码（如 `鈥?`）

**原因：** PowerShell 管道默认使用 GBK 编码，而脚本输出 UTF-8

**解决方案（3 选 1）：**

### 方案 1：直接运行（推荐）
```powershell
python insert_creators.py --batch 50
```
不使用管道（`|`），直接输出到控制台，通常不会乱码。

### 方案 2：设置 PowerShell 编码
```powershell
$OutputEncoding = [System.Text.Encoding]::UTF8
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
python insert_creators.py --batch 50
```

### 方案 3：重定向到文件
```powershell
python insert_creators.py --batch 50 > output.txt
# 用支持 UTF-8 的编辑器打开 output.txt（如 VS Code）
```

**重要：** 即使显示乱码，脚本功能仍正常工作，AI 仍能正确分析路径。乱码只影响显示，不影响数据处理。
